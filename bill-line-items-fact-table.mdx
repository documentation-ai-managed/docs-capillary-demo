The Bill Line Items fact table is a comprehensive data structure that captures detailed transaction information at both the bill and line item levels. This table serves as a central repository for analyzing customer purchases, loyalty points, discounts, taxes, and various transaction attributes.

## Overview

This fact table combines data from multiple sources including bills, line items, combo details, shipping information, and extended fields to provide a complete view of transaction data. Each record represents a line item within a transaction, along with associated bill-level information.

## Field Reference

### Financial Measures

<ExpandableGroup>
<Expandable title="Bill-level Financial Fields" default-open="false">
| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| bill_amount | double | Net amount of the transaction after adjusting any discounts, taxes, etc. Final amount customer pays | Bill Amount |
| bill_discount | double | Total discount applied on the bill. Includes flat discount, percentage discount, etc. | Bill Discount |
| initial_bill_value | double | Original bill amount before any discounts or taxes are applied | Initial Bill Value |
| tax_amount | double | Total amount of tax levied on the bill | Tax Amount |

<Callout kind="info">
The `bill_amount` represents the final amount after all adjustments, while `initial_bill_value` shows the original transaction value before any modifications.
</Callout>
</Expandable>

<Expandable title="Line Item Financial Fields" default-open="false">
| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| line_item_amount | double | Total amount for the line item after discounts and taxes have been applied | Line Item Amount |
| line_item_discount | double | Discount given for the particular line item | Line Item Discount |
| initial_line_item_value | double | Original value of a line item before any discounts or taxes are applied | Initial Line Item Value |
| rate | double | Total cost of a line item, obtained by multiplying item price by quantity purchased | Rate |
| quantity | double | Number of units/line items bought | Quantity |
| total_unit_cost | double | Total price of the item including tax and other charges | Total Unit Cost |
| item_unit_margin | double | Profit margin associated with the item | Item Unit Margin |

<Callout kind="tip">
Use `initial_line_item_value` and `line_item_amount` together to calculate the effective discount percentage on each item.
</Callout>
</Expandable>

<Expandable title="Discount Fields" default-open="false">
| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| additional_discount | double | Extra discount availed on a transaction (e.g., combo or bulk items discount) | Additional Discount |
| item_coupon_discount | double | Discount applied to the line item using coupons | Item Coupon Discount |
| item_point_discount | double | Discount applied to the line item using loyalty points | Item Points discount |
| item_discount_description | string | Description of why the discount has been applied to the item | Item Discount Description |
</Expandable>
</ExpandableGroup>

### Tax Fields

<Tabs>
<Tab title="Bill-level Taxes" icon="file-text">
| Field Name | Data Type | Description | Measure Name |

<Tab title="Line Item Taxes" icon="list">
| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|

| lineitem_integrated_gst | double | Integrated GST levied by the Central Government on the line item | Lineitem Integrated Gst |

|------------|-----------|-------------|--------------|

## Data Quality Notes

<Callout kind="alert">
**Primary Keys**: This table has `bill_id` as the primary key at the bill level and `line_item_id` as the primary key for individual line items. Ensure these fields are unique for data integrity.
</Callout>

<Callout kind="info">
**Extended Fields**: Some fields like `additional_discount` are extended fields that take user input values. Ensure proper validation when populating these fields.
</Callout>

<Callout kind="tip">
**Combo Items**: When analyzing combo items, use `parent_line_item_id` to link child items to their parent combo items for accurate reporting.
</Callout>

## Best Practices

<Steps>
<Step title="Join with Dimension Tables" icon="link" title-type="h4">
Always join this fact table with relevant dimension tables using the `dim_*` fields to get descriptive information about customers, items, stores, and other attributes.
</Step>

<Step title="Filter by Date Range" icon="calendar" title-type="h4">
Use `dim_event_date_id` to filter transactions within specific date ranges for time-based analysis.
</Step>

<Step title="Handle Null Values" icon="alert-circle" title-type="h4">
Some fields may contain null values, especially in extended fields. Always account for nulls in your queries and calculations.
</Step>

<Step title="Aggregate Appropriately" icon="sigma" title-type="h4">
When aggregating measures, ensure you're using the correct aggregation function (SUM for amounts, COUNT for quantities, AVG for percentages).
</Step>

<Step title="Consider Transaction Context" icon="context" title-type="h4">
Use `dim_source_type_id` and `dim_order_channel_id` to differentiate between in-store and online transactions for accurate channel analysis.
</Step>
</Steps>
