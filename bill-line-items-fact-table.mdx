The Bill Line Items fact table is a comprehensive data structure that captures detailed transaction information at both the bill and line item levels. This table serves as a central repository for analyzing customer purchases, loyalty points, discounts, taxes, and various transaction attributes.

## Overview

This fact table combines data from multiple sources including bills, line items, combo details, shipping information, and extended fields to provide a complete view of transaction data. Each record represents a line item within a transaction, along with associated bill-level information.

## Key Metrics

- **Transaction Metrics**: Track bill amounts, discounts, and item quantities across all transactions
- **Loyalty Metrics**: Monitor allocated and redeemed loyalty points for customer engagement analysis
- **Tax Metrics**: Analyze various tax components including GST, VAT, and service taxes

## Field Reference

### Financial Measures

#### Bill-level Financial Fields

| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| bill_amount | double | Net amount of the transaction after adjusting any discounts, taxes, etc. Final amount customer pays | Bill Amount |
| bill_discount | double | Total discount applied on the bill. Includes flat discount, percentage discount, etc. | Bill Discount |
| initial_bill_value | double | Original bill amount before any discounts or taxes are applied | Initial Bill Value |
| tax_amount | double | Total amount of tax levied on the bill | Tax Amount |

The `bill_amount` represents the final amount after all adjustments, while `initial_bill_value` shows the original transaction value before any modifications.

#### Line Item Financial Fields

| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| line_item_amount | double | Total amount for the line item after discounts and taxes have been applied | Line Item Amount |
| line_item_discount | double | Discount given for the particular line item | Line Item Discount |
| initial_line_item_value | double | Original value of a line item before any discounts or taxes are applied | Initial Line Item Value |
| rate | double | Total cost of a line item, obtained by multiplying item price by quantity purchased | Rate |
| quantity | double | Number of units/line items bought | Quantity |
| total_unit_cost | double | Total price of the item including tax and other charges | Total Unit Cost |
| item_unit_margin | double | Profit margin associated with the item | Item Unit Margin |

Use `initial_line_item_value` and `line_item_amount` together to calculate the effective discount percentage on each item.

#### Discount Fields

| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| additional_discount | double | Extra discount availed on a transaction (e.g., combo or bulk items discount) | Additional Discount |
| item_coupon_discount | double | Discount applied to the line item using coupons | Item Coupon Discount |
| item_point_discount | double | Discount applied to the line item using loyalty points | Item Points discount |
| item_discount_description | string | Description of why the discount has been applied to the item | Item Discount Description |

### Tax Fields

#### Bill-level Taxes

| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| central_gst | double | GST tax levied by the Central Government | Central Gst |
| state_gst | double | Taxes levied by the State Government on the bill | State Gst |
| integrated_gst | double | GST levied by the Central Government for inter-state trade | Integrated Gst |
| tax_amount | double | Total amount of tax levied on the bill | Tax Amount |

#### Line Item Taxes

| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| lineitem_central_gst | double | GST levied by the Central Government on the line item | Lineitem Central Gst |
| lineitem_state_gst | double | State GST applicable to the line item | Lineitem State Gst |
| lineitem_integrated_gst | double | Integrated GST levied by the Central Government on the line item | Lineitem Integrated Gst |
| lineitem_service_tax_amount | double | Amount of service tax applicable to the line item | Lineitem Service Tax Amount |
| lineitem_service_tax_percentage | double | Percentage of service tax levied to the line item | Lineitem Service Tax Percentage |
| lineitem_vat_amount | double | Amount of VAT levied by the Central Government on the line item | Lineitem Vat Amount |
| lineitem_vat_tax_percentage | double | Percentage of VAT levied by the Central Government on the line item | Lineitem Vat Tax Percentage |

GST (Goods and Services Tax) is divided into three types: Central GST for intra-state transactions, State GST for intra-state transactions, and Integrated GST for inter-state trade.

### Loyalty and Points

| Field Name | Data Type | Description | Measure Name |
|------------|-----------|-------------|--------------|
| allocated_points | double | Number of loyalty points allocated to a customer for a specific transaction. Can be at bill, line item, or customer level | Allocated Points |
| redeemed_points | double | Points redeemed on the bill level | Redeemed Points |

Loyalty points drive customer engagement. Track both `allocated_points` and `redeemed_points` to understand the effectiveness of your loyalty program.

### Identifiers

#### Bill Identifiers

| Field Name | Data Type | Description |
|------------|-----------|-------------|
| bill_id | bigint | Unique identifier assigned to a bill internally by Capillary system (Primary Key) |
| bill_number | string | Unique identifier for the transaction (auto-generated or manual) |
| converted_bill_id | bigint | The new bill id after conversion from non-loyal to loyal customer |

`bill_id` is the primary key and is system-generated, while `bill_number` is the transaction identifier used at the POS.

#### Line Item Identifiers

| Field Name | Data Type | Description |
|------------|-----------|-------------|
| line_item_id | bigint | Unique identifier generated by the system for the line item (Primary Key) |
| item_code | string | Unique code assigned to a line item within the transaction |
| parent_line_item_id | bigint | Identifier of the parent line item (for combo or add-on items) |
| lineitem_serial_number | string | Unique serial number of the line-item |
| lineitem_uuid | string | Universally unique identifier (UUID) assigned to the line item |

## Common Use Cases

- **Sales Analysis**: Analyze transaction patterns, bill amounts, and item-level sales performance across different time periods and customer segments.
- **Discount Analysis**: Track discount effectiveness by analyzing various discount types, reasons, and their impact on transaction values.
- **Loyalty Program Analysis**: Monitor loyalty point allocation and redemption patterns to measure program effectiveness and customer engagement.
- **Tax Compliance**: Generate tax reports by analyzing GST, VAT, and other tax components at bill and line item levels.
- **Customer Behavior**: Understand customer purchasing patterns using visit counts, repeat status, and days since last visit metrics.
- **Inventory Analysis**: Track item-level sales, quantities, and product performance using line item data and item dimensions.

## Data Quality Notes

**Primary Keys**: This table has `bill_id` as the primary key at the bill level and `line_item_id` as the primary key for individual line items. Ensure these fields are unique for data integrity.

**Extended Fields**: Some fields like `additional_discount` are extended fields that take user input values. Ensure proper validation when populating these fields.

**Combo Items**: When analyzing combo items, use `parent_line_item_id` to link child items to their parent combo items for accurate reporting.

## Best Practices

1. **Join with Dimension Tables**: Always join this fact table with relevant dimension tables using the `dim_*` fields to get descriptive information about customers, items, stores, and other attributes.

2. **Filter by Date Range**: Use `dim_event_date_id` to filter transactions within specific date ranges for time-based analysis.

3. **Handle Null Values**: Some fields may contain null values, especially in extended fields. Always account for nulls in your queries and calculations.

4. **Aggregate Appropriately**: When aggregating measures, ensure you're using the correct aggregation function (SUM for amounts, COUNT for quantities, AVG for percentages).

5. **Consider Transaction Context**: Use `dim_source_type_id` and `dim_order_channel_id` to differentiate between in-store and online transactions for accurate channel analysis.
