title: "Get Customer Details"
description: "Retrieve comprehensive customer information from a specific source including profile data, loyalty details, and transaction history"
---

The Get Customer Details API retrieves detailed information about a customer from a specific source. You can use the `embed` parameter to fetch specific details as required, allowing for flexible and efficient data retrieval.

## API Endpoint

```
GET https://{host}/v2/customers/{customerId}
```

## Authentication

This API uses Basic Authentication. You must provide a valid username and password encoded in Base64 format.

<Callout kind="info">
Include the Authorization header in your request: `Authorization: Basic {base64_encoded_credentials}`
</Callout>

## Request

<Request tabs="cURL,JavaScript,Python">
```bash
curl -X GET 'https://{host}/v2/customers/{customerId}?embed=points,subscriptions,referrals' \
  -H 'Authorization: Basic BASE64_ENCODED_CREDENTIALS' \
  -H 'Content-Type: application/json'
```

```javascript
const customerId = '12345';
const embedParams = 'points,subscriptions,referrals';

const response = await fetch(
  `https://{host}/v2/customers/${customerId}?embed=${embedParams}`,
  {
    method: 'GET',
    headers: {
      'Authorization': 'Basic ' + btoa('username:password'),
      'Content-Type': 'application/json'
    }
  }
);

const customerData = await response.json();
console.log(customerData);
```

```python
import requests
import base64

customer_id = '12345'
embed_params = 'points,subscriptions,referrals'

# Encode credentials
credentials = base64.b64encode(b'username:password').decode('utf-8')

headers = {
    'Authorization': f'Basic {credentials}',
    'Content-Type': 'application/json'
}

response = requests.get(
    f'https://{{host}}/v2/customers/{customer_id}',
    params={'embed': embed_params},
    headers=headers
)

customer_data = response.json()
print(customer_data)
```
</Request>

## Path Parameters

<ParamField path="customerId" param-type="string" required="true">
Unique identifier of the customer whose details you want to retrieve. This can be:

- Internal customer ID assigned by Capillary
- Mobile number (with country code)
- Email address
- External customer ID from your system

**Example**: `98765432101`, `customer@example.com`, `EXT_CUST_001`
</ParamField>

## Query Parameters

<ParamField query="embed" param-type="string" required="false">
Comma-separated list of additional customer details to include in the response. Use this parameter to fetch specific data and optimize API performance.

**Available embed options**:

| Value | Description |
|-------|-------------|
| `points` | Loyalty points balance and history |
| `subscriptions` | Customer communication subscriptions |
| `referrals` | Referral program details and status |
| `extended_fields` | Custom extended fields configured for your organization |
| `segments` | Customer segment memberships |
| `mlp` | Multi-level program details |
| `lifetime_points` | Total lifetime points earned |
| `lifetime_purchases` | Lifetime purchase statistics |
| `communication_preferences` | Channel-wise communication preferences |

**Example**: `embed=points,subscriptions,referrals`

<Callout kind="tip">
Only request the data you need using the `embed` parameter to improve response times and reduce bandwidth usage.
</Callout>
</ParamField>

<ParamField query="source" param-type="string" required="false">
Source from which customer data should be retrieved. Use this when the customer is registered across multiple sources.

**Possible values**:
- `INSTORE` - In-store registration
- `WECHAT` - WeChat integration
- `FACEBOOK` - Facebook integration
- `WEB` - Website registration
- `MOBILE_APP` - Mobile application

**Example**: `source=INSTORE`
</ParamField>

<ParamField query="identifierType" param-type="string" required="false">
Type of identifier provided in the `customerId` path parameter. Helps the API accurately locate the customer.

**Possible values**:
- `id` - Internal Capillary customer ID
- `mobile` - Mobile number
- `email` - Email address
- `external_id` - External customer ID
- `card_number` - Loyalty card number

**Default**: `id`

**Example**: `identifierType=mobile`
</ParamField>

## Best Practices

<Steps>
<Step title="Use specific identifiers" icon="fingerprint" title-type="h3">
When possible, use internal customer IDs rather than email or mobile for faster lookups. If using email or mobile, always specify the `identifierType` parameter.

<Callout kind="tip">
Internal IDs provide the fastest query performance as they are the primary key in the database.
</Callout>
</Step>

<Step title="Request only needed data" icon="zap" title-type="h3">
Use the `embed` parameter judiciously. Only request additional data that you actually need for your use case.

**Good practice**:

```bash
# Only get points if you need them
GET /v2/customers/12345?embed=points
```

**Avoid**:

```bash
# Don't request everything if you only need basic info
GET /v2/customers/12345?embed=points,subscriptions,referrals,segments,lifetime_purchases
```
</Step>

<Step title="Handle errors gracefully" icon="shield" title-type="h3">
Always check the `status.success` field and handle different error codes appropriately.

<CodeGroup tabs="JavaScript,Python">
```javascript
const response = await fetch(url, options);
const data = await response.json();

if (!data.status.success) {
  switch (data.status.code) {
    case 404:
      console.log('Customer not found');
      break;
    case 401:
      console.log('Authentication failed');
      break;
    default:
      console.log('An error occurred:', data.status.message);
  }
  return;
}

// Process customer data
console.log(data.customer);
```

```python
response = requests.get(url, headers=headers)
data = response.json()

if not data['status']['success']:
    code = data['status']['code']
    if code == 404:
        print('Customer not found')
    elif code == 401:
        print('Authentication failed')
    else:
        print(f"An error occurred: {data['status']['message']}")
    return

# Process customer data
print(data['customer'])
```
</CodeGroup>
</Step>

<Step title="Cache responses when appropriate" icon="database" title-type="h3">
If customer data doesn't change frequently in your use case, implement caching to reduce API calls and improve performance.

<Callout kind="success">
Caching customer data can reduce API calls by up to 70% for read-heavy applications.
</Callout>
</Step>

<Step title="Secure your credentials" icon="lock" title-type="h3">
Never expose your API credentials in client-side code. Always make API calls from your backend server.

<Callout kind="alert">
Store credentials in environment variables or secure secret management systems, never in source code.
</Callout>
</Step>
</Steps>

## Rate Limiting

<Callout kind="info">
The Get Customer Details API has the following rate limits:

- **200 requests per minute** per API key
- **5000 requests per hour** per API key

If you exceed these limits, you'll receive a `429 Too Many Requests` response. Implement exponential backoff when rate limits are hit.
</Callout>

## FAQs

<ExpandableGroup>
<Expandable title="Can I retrieve multiple customers in a single API call?" default-open="false">
No, this endpoint retrieves one customer at a time. For bulk customer data retrieval, use the bulk export APIs or contact support for batch processing options.
</Expandable>

<Expandable title="How often is customer data updated?" default-open="false">
Customer data is updated in real-time as transactions occur. The `updated_on` timestamp indicates when the customer record was last modified.
</Expandable>

<Expandable title="What happens if I request an invalid embed parameter?" default-open="false">
The API will return a 400 Bad Request error with details about which embed parameter is invalid and what the valid options are.
</Expandable>

<Expandable title="Can I use this API to search for customers?" default-open="false">
This API requires a specific customer identifier. For searching customers by partial name, email domain, or other criteria, use the customer search API endpoint.
</Expandable>

<Expandable title="How do I handle customers registered across multiple sources?" default-open="false">
Use the `source` query parameter to specify which source to retrieve data from. If not specified, the API returns data from the primary source associated with the customer identifier.
</Expandable>

<Expandable title="Are there any fields that are always returned regardless of embed parameter?" default-open="false">
Yes, basic customer information (id, name, email, mobile, registration date, type, source) is always returned. Additional details require the appropriate `embed` parameter.
</Expandable>
</ExpandableGroup>
