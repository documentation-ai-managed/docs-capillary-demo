## What is Capillary?

Capillary Technologies is a loyalty management platform that helps enterprises boost customer retention, engagement, and revenue. It is positioned as an AI-first, managed SaaS loyalty solution, operating at scale with:

- 1.2 Bn+ loyalty members

- 390+ brands across 100+ loyalty programs

- 1.95 Bn+ annual transactions

- 99.99% system uptime

This documentation focuses on how you, as a developer or solution engineer, can work with Capillary APIs and core data structures to power loyalty and campaign use cases.

<Callout kind="info" collapsed="false">
  This is a **Capillary Demo** documentation set. It is designed to illustrate typical integration and configuration patterns, not to replace your official Capillary implementation guides or contracts.
</Callout>

## Who this documentation is for

This site is intended for:

- Backend and integration engineers calling Capillary APIs.

- Solution engineers designing loyalty and promotion journeys.

- Data and analytics teams working with campaign and billing fact tables.

You should be comfortable with REST APIs and basic JSON payloads.

## What's in these docs

These docs provide:

- **Customer APIs** – fetching core customer data to drive personalized experiences.

- **Promotions APIs** – creating and managing cart-level promotions and offers.

- **Campaign configurations** – defining referral campaigns and understanding how events are recorded.

- **Fact tables** – reference for transactional and campaign data structures such as bill line items.

Each page focuses on a specific task or data contract so you can quickly plug Capillary capabilities into your existing architecture.

## Suggested reading path

If you are new to this demo set, a good starting flow is:

1. **Understand core customer access**

   - Read **Get Customer Details** to see how to retrieve customer profiles via API.

   - Focus on how identifiers are passed and which fields are typically used for loyalty decisions.

2. **Explore promotions and cart logic**

   - Go through **Create Cart Promotion** to understand how cart-level promotional rules are defined and invoked from your commerce stack.

3. **Review campaign configuration**

   - Study **Referral Campaign** to see how a simple referral-based engagement flow is modeled and configured.

4. **Connect to data and analytics**

   - Check **Bill Line Items Fact Table** to understand how transactions and line items are stored for reporting, attribution, and downstream analytics.

You may not need every section; pick the ones that match your immediate implementation scope.
